# US-007: Validasi lintas layer

**Prioritas:** Must · **Kebutuhan:** FR-7, NFR-3 · **Status:** Sedang dikerjakan, menunggu CI

## Story

Sebagai **pemilik data**, saya ingin data tidak valid ditolak di frontend dan backend, agar database tetap benar meskipun API dipanggil langsung.

## Kriteria penerimaan

1. **Diberikan** setiap aturan pada [PRD §5](../PRD.md#5-aturan-validasi), **ketika** nilai melanggar aturan itu, **maka** frontend dan backend sama-sama menolaknya.
2. **Diberikan** nilai tepat di batas, seperti latitude `90`, longitude `-180`, koordinat `0,0`, atau nama 100 karakter, **ketika** dikirim, **maka** nilai diterima.
3. **Diberikan** request langsung ke API dengan banyak field salah, **ketika** diproses, **maka** respons 422 memuat semua error dengan `field`, `code`, dan `message`.
4. **Diberikan** JSON rusak atau field tidak dikenal, **ketika** dikirim, **maka** API membalas 400.
5. **Diberikan** body lebih dari 64 KiB, **ketika** dikirim, **maka** API membalas 413.
6. **Diberikan** `Content-Type` selain JSON, **ketika** dikirim, **maka** API membalas 415.
7. **Diberikan** semua jenis kegagalan, **ketika** respons dikirim, **maka** bentuknya tetap envelope standar dan `code` sama dengan status HTTP.

## Pengujian

- Table-driven test Go dan Vitest memakai kasus yang sama, termasuk nilai batas.
- Koleksi Postman di `postman/` menguji kontrak terhadap server yang berjalan.
- Test backend memastikan setiap kode error sesuai tabel PRD.
